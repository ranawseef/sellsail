# SellSail SaaS: build plan and handoff

Branch: `feature/saas-app`. Never push to `main`: the owner merges, and Hostinger
auto-deploys `main` (Next.js 16.4.1 standalone under Passenger, Node 22).
Read `CLAUDE.md` and `AGENTS.md` first. This Next 16 has breaking changes:
`middleware` is now `proxy.ts`, so read `node_modules/next/dist/docs` before writing
app code. `cacheComponents` is off. Builds stay on webpack with one worker
(`next.config.ts`) because of Hostinger's process limit.

Do not develop on the Hostinger server itself. Its thread limit is shared with the
live sites, and builds or local databases there crash the session.

## Product

An Amazon → OnBuy dropshipping repricer for UK sellers, now multi-tenant.
AliExpress (source) and eBay (marketplace) come in later phases, and the data
model already allows for them: `source_accounts.source` and
`marketplace_accounts.marketplace`. Show them as "coming soon" in the UI.

## Change (2026-10-25): SellSail's own Amazon keys, optional proxy

- **Amazon:** sellers no longer connect Amazon. Prices are read with SellSail's
  own SP-API key sets from env (`SPAPI_1_CLIENT_ID` / `_CLIENT_SECRET` /
  `_REFRESH_TOKEN`, up to 20 sets). The sets form a pool shared by every
  workspace (`amazon_apps` holds each set's token, call slot and health); each
  reprice batch reserves the next free set. A set Amazon refuses sits out for
  15 minutes. One reprice job per workspace (`target_id` 0). Optional
  `SPAPI_PROXY` sends Amazon calls through one proxy. Migration 007 deleted any
  seller-provided Amazon keys and the Seller Central OAuth route is gone.
- **Proxy:** optional. No proxy means OnBuy calls go direct from the server.
  A saved proxy is never bypassed: while it is unreadable or failing, nothing
  is sent to OnBuy until it is fixed or removed (Connections → Remove).
  `egressFetch` takes an explicit `Route` (`proxy` or `direct`), so no caller
  can fall back to direct by passing null.
- **Wizard:** three steps (OnBuy, Pricing, Import); the proxy is an optional
  fold-out in the OnBuy step.

## Change (2026-11-02): Amazon key sets in the database

- SPAPI_n_* vars saved in Hostinger's hPanel never reached the running app
  (the /admin/system Key check showed no SPAPI names while other vars
  arrived), so key sets are now added by admins on /admin/system and kept in
  `amazon_app_keys` (migration 012): one row per slot, a name, an enabled
  flag, who/when, and the client id, client secret and refresh token sealed
  together with APP_ENCRYPTION_KEY, bound to the slot. Only the client id's
  last four characters are stored in the clear.
- The pool (`configuredApps()`, now async) is env sets plus enabled stored
  sets, by slot; an env set wins a clash. Decrypted sets are cached for 60 s
  per process and the cache is cleared on every admin change (other processes
  catch up within 60 s). Reservation, backoff and health are unchanged and
  still live in `amazon_apps`.
- Admin actions: add, replace keys, pause/resume, delete, and Test (asks
  Login with Amazon for a token, reports only success or a fixed message).
  Each checks the admin session, validates with zod and writes `admin_audit`
  without any key value.
- **Home page:** `InsideLook`, an animated dashboard preview with demo data.


## Change (2026-11-02, later): customer activity in the admin panel

- **Recording** (`src/server/activity.ts`, types in `src/lib/activity.ts`):
  `recordActivity()` writes one `user_activity` row (migration 013) and never
  throws. Server-side only: sign-in events, OnBuy/proxy changes and failed
  tests, imports and CSV results, repricer settings (names, never values),
  pause/resume, billing changes from the Stripe webhook, and every error a
  dashboard action shows. Details are cleaned (secret-sounding keys dropped,
  key/token/card/email-looking text masked); IP only on `auth.*` rows.
- **Jobs**: `job_runs` now stores per-run counts. Instead of a row per run,
  the hourly maintenance writes one `reprice.hourly` / `stock_sync.hourly`
  summary per workspace and hour with work in it, plus rows when a job starts
  failing or recovers and the first reprice / first price change
  (`tenants.first_reprice_at`, `first_price_change_at`).
- **Retention**: 12 months, by the hourly maintenance. Rows cascade from
  `users` and `tenants`, so `deleteWorkspace()` removes them.
- **Admin**: `/admin/users/[id]` and `/admin/workspaces/[id]/activity`
  (summary, onboarding checklist, repricer health, recent problems, filtered
  timeline); "Needs attention" on `/admin` (rules in
  `src/server/admin/activity-rules.ts`). Every admin page checks the session
  itself; each activity view writes `admin_audit`.
- **Amazon key sets**: Test now records the set's status, last OK and last error.

## Change (2026-10-25, later): competition and admin

- **Competition** (`src/lib/competition.ts`, `src/server/jobs/compete.ts`,
  `/app/competition`). A `compete` job per OnBuy account calls
  `GET /listings/check-winning` (JSON body, 100 SKUs) and stores the leader's
  price on each product. The undercut is applied inside `decide()`/`listPrice()`,
  so Amazon repricing and settings changes keep it instead of undoing it.
  Floor: "protect profit" keeps `min_profit` after fees, "win the sale" allows
  `max_loss` after fees. The band price is always the ceiling. A leader price is
  trusted for 6 h, then the band price is tried again. Off by default.
  Check interval per plan: 30 / 30 / 15 / 10 min.
- **Admin panel** (`/admin`, `src/server/admin/*`). Sign-in by a 6-digit code
  emailed to an address in `ADMIN_EMAILS` (default hello@sellsail.io); 12 h
  sessions in `admin_sessions`; every change in `admin_audit`. Pages:
  overview, workspaces (plan/status, trial days, pause, run jobs), users
  (mark verified, sign out), system health, audit log.
- **Email**: automated mail is meant to come from no-reply@ (`SMTP_USER`),
  with `Reply-To` hello@ (`MAIL_REPLY_TO`).
- Migrations 008_competition and 009_admin.
